# Hardware Bring-up Guide

> Этот файл — инструкция для AI-ассистента (Claude). Пользователь будет
> подключать датчик, экран, кнопки и батарейный бокс поэтапно и спрашивать
> «что делать». Здесь — runbook: точные команды, ожидаемый вывод и дерево
> диагностики на случай если что-то пошло не так.
>
> Когда пользователь говорит «приступаю к проверке этапа N» / «не работает
> X» / «прошил, что дальше» — открывай этот файл и веди по нему. Не
> пропускай этапы и не гадай, если что-то не описано — спроси.

---

## Общие принципы работы

1. **Поэтапная проверка.** Не прошивать сразу финал. Идти от Этапа 1 к 14,
   на каждом ждать подтверждения пользователя что всё ок. Если что-то не
   работает — чинить здесь и сейчас, не «потом разберёмся».

2. **Источник истины — Serial Monitor.** Логи в Serial показывают точно
   что происходит в прошивке. Перед диагностикой по визуалу всегда сначала
   просим пользователя прислать содержимое Serial.

3. **Безопасность железа.** Перед каждым изменением проводки —
   отключить USB. Перед подключением батарейного бокса —
   проверить полярность мультиметром (`+4.5 В` на красном относительно
   чёрного). Перепутанная полярность сжигает ESP.

4. **Только один источник питания.** Либо USB, либо батареи. НЕ оба
   одновременно (можно потерять данные на LittleFS).

5. **Что чинить в коде vs что чинить руками.** Программные параметры,
   которые часто нужно менять под конкретное железо, перечислены в
   разделе «Параметры для подкрутки» в конце файла.

## Pre-flight чек-лист (перед первой прошивкой)

Спросить пользователя, что готово:

- [ ] ESP32-S3 SuperMini + USB кабель **данных** (charge-only не подойдёт).
- [ ] SCD41 на отдельном модуле с pull-up резисторами на SDA/SCL
      (обычно встроенные 10 кΩ — у Adafruit/Sparkfun точно есть).
- [ ] Waveshare 2.13" e-Paper HAT (250×122 ч/б) + шлейф 8 проводов.
- [ ] 2 тактовых кнопки.
- [ ] Бокс под 3× AA (но **батарейки пока НЕ вставлены**).
- [ ] Мультиметр (хотя бы прозвонка + измерение напряжения).
- [ ] PlatformIO CLI работает: `pio --version`.

Если что-то отсутствует — это не блокер для соответствующих ранних
этапов. SCD41 нужен с Этапа 2, e-Paper с Этапа 3, кнопки с Этапа 6,
батарейки с Этапа 14.

## Общие команды

Запоминать не нужно, копируй пользователю по необходимости:

```bash
# Просмотр доступных портов (узнать какой COM)
pio device list

# Сборка под текущий чекаут
pio run -e esp32-s3-supermini

# Прошивка
pio run -e esp32-s3-supermini -t upload

# Открыть Serial monitor (Ctrl+C для выхода)
pio device monitor

# Полная очистка flash (полезно перед первой прошивкой
# или если LittleFS повредился)
pio run -e esp32-s3-supermini -t erase

# Прошивка + сразу monitor
pio run -e esp32-s3-supermini -t upload -t monitor

# Переключиться на нужный этап
git checkout <commit_hash>
# Вернуться на финальный код:
git checkout main
```

### Если upload не входит в bootloader

ESP32-S3 SuperMini иногда не входит автоматически:

1. Зажать кнопку **BOOT** на плате.
2. Кратко нажать **RESET**.
3. Отпустить BOOT.
4. Сразу запустить upload.

После успешной прошивки нажать RESET для нормального старта.

### Этап 1 — Hello World

| | |
|---|---|
| Commit | `b17d807` |
| Подключения | Только USB |
| Цель | Serial вывод + (опционально) моргание LED |

**Команды:**
```bash
git checkout b17d807
pio run -e esp32-s3-supermini -t erase     # один раз, чистая flash
pio run -e esp32-s3-supermini -t upload -t monitor
```

**Ожидаемый Serial:**
```
============================
Stage 1: Hello, ESP32-S3!
============================
LED on GPIO 48 (assumed RGB WS2812)
Blinking every 500 ms...
[1] Blink ON
[2] Blink OFF
[3] Blink ON
...
```

**Визуально:** красный LED моргает ~раз в секунду (если на плате есть RGB
WS2812 на GPIO 48).

**Диагностика:**
- ❌ **Ничего в Serial.**
  - Возможно USB кабель charge-only — поменять.
  - Bootloader не вошёл — BOOT+RESET процедура.
  - Не тот COM — `pio device list`, потом `pio device monitor -p <port>`.
- ❌ **Serial есть, но "Blink ON" не идёт.**
  - setup() упал на чём-то странном. Прислать полный вывод.
- ❌ **LED не моргает, но Serial работает.**
  - Это OK на Этапе 1. LED может быть не на GPIO 48, не быть RGB, или
    отсутствовать на конкретной партии SuperMini. Переход на следующий
    этап.

### Этап 2 — SCD41

| | |
|---|---|
| Commit | `a67ca2d` |
| Подключения | USB + 4 провода SCD41 |
| Цель | Чтение CO2/T/H каждые 5 сек |

**Проводка SCD41:** VDD → 3V3, GND → GND, SDA → GPIO 8, SCL → GPIO 9.
I2C адрес 0x62.

**Команды:**
```bash
git checkout a67ca2d
pio run -e esp32-s3-supermini -t upload -t monitor
```

**Ожидаемый Serial:**
```
Stage 2: SCD41 readout
SCD41 OK. Serial: 0x123456789abc
[1] CO2: 645 ppm, T: 23.4°C, H: 45%
[2] CO2: 651 ppm, T: 23.5°C, H: 44%
...
```

**Валидные диапазоны:** CO2 400–2000 в помещении, T 18–28°C, H 30–70%.
Первые 10 минут T может быть завышена на ~1°C (саморазогрев датчика).

**Диагностика:**
- ❌ **"SCD41 not responding"** / "getSerialNumber: 0xNNN".
  - Проверить мультиметром: 3.3 В между VDD и GND на самом модуле.
  - Прозвонить SDA (GPIO 8 ↔ модуль) и SCL (GPIO 9 ↔ модуль).
  - На модуле SCD41 SDA/SCL могут быть перепутаны местами — пробуй
    переставить.
  - Адрес: некоторые клоны на 0x61 вместо 0x62 — это будет уже хардкорная
    отладка, спросить у пользователя точную модель/фото.
- ❌ **"CO2=0 (sensor not ready)"** периодически.
  - Норма для первых 1–2 циклов после включения. Если длится дольше
    минуты — плохой контакт по I2C.
- ❌ **Дикие значения (CO2 > 5000 в проветренной комнате, T = -40, и т.п.).**
  - Плохой контакт на SDA/SCL. Прижать провода, перепаять.

### Этап 3 — E-Paper Hello

| | |
|---|---|
| Commit | `2655384` |
| Подключения | USB + 8 проводов e-Paper |
| Цель | Картинка «Hello, e-Paper!» на экране |

**Проводка e-Paper HAT:** VCC → 3V3, GND → GND, DIN → GPIO 11,
CLK → GPIO 12, CS → GPIO 10, DC → GPIO 13, RST → GPIO 6, BUSY → GPIO 7.

**Команды:**
```bash
git checkout 2655384
pio run -e esp32-s3-supermini -t upload -t monitor
```

**Ожидаемый Serial:**
```
Stage 3: E-Paper Hello
Display size: 250 x 122
Display updated. Picture should remain visible.
```

**Визуально:** на экране надпись «Hello, e-Paper!» крупным шрифтом,
ниже «Stage 3 OK», рамка по периметру. Картинка остаётся даже после
выдёргивания USB — это нормально для e-Paper.

**Диагностика:**
- ❌ **Экран полностью белый или показывает мусор.**
  - **Самая частая причина** — неподходящий драйвер. В `src/main.cpp`
    найти `#define EPD_DRIVER GxEPD2_213_B73`. Перебрать по очереди:
    `GxEPD2_213_B72`, `GxEPD2_213_BN`, `GxEPD2_213_DEPG0213BN`. После
    каждой смены — пересобрать и перепрошить.
  - Проверить пины DC и BUSY — их часто путают.
  - Проверить питание e-Paper (3.3 В).
- ❌ **Экран показал картинку, но потом помех / полос.**
  - Кабель шлейфа неплотно вставлен.
- ❌ **На экране отзеркаленный / повёрнутый текст.**
  - В `init_display` поменять `display.setRotation(1)` на 0/2/3.

### Этап 5 — Deep sleep

| | |
|---|---|
| Commit | `a93be5a` |
| Подключения | USB + SCD41 + e-Paper |
| Цель | Цикл wake → measure → display → sleep (5 мин) |

**Команды:**
```bash
git checkout a93be5a
pio run -e esp32-s3-supermini -t erase     # сбросить RTC memory
pio run -e esp32-s3-supermini -t upload -t monitor
```

**Ожидаемый Serial при первом включении:**
```
Stage 5: Deep sleep
First boot — RTC memory initialized
Wake #1, cause: 0, prior uptime: 0 sec
SCD41 OK. SN: 0x...
First wake: showing warmup screen
CO2: 645 ppm, T: 23.4 C, H: 45 %
Total uptime so far: 6 sec. Sleeping for 300 sec.
```

После этого 5 минут тишины, потом следующее пробуждение:
```
Stage 5: Deep sleep
Wake #2, cause: 4, prior uptime: 6 sec
SCD41 OK. SN: 0x...
CO2: 648 ppm, T: 23.4 C, H: 45 %
Total uptime so far: 13 sec. Sleeping for 300 sec.
```

**Визуально:**
- При первом включении: «Warming up sensor... Please wait» (partial refresh,
  без мерцания), через ~5 сек — три значения CO2/T/H (full refresh).
- На последующих пробуждениях экран обновляется новыми значениями.

**Диагностика:**
- ❌ **После первого цикла Serial умолкает навсегда.**
  - Если есть мультиметр на USB: должно быть < 30 мА в sleep. Если 50+ —
    что-то не уснуло.
  - Проверить что сообщение «Sleeping for 300 sec» появилось.
- ❌ **`Wake #1` повторяется при каждом пробуждении.**
  - RTC memory не сохраняется. Возможно неправильная инициализация
    `rtc_magic`. Прислать полный лог.
- ❌ **Welcome screen остался на экране, новые значения не появились.**
  - Измерение не отработало или draw не вызвался. Лог в Serial.

### Этап 6 — Кнопки

| | |
|---|---|
| Commit | `7c11374` |
| Подключения | USB + SCD41 + e-Paper + 2 кнопки |
| Цель | Wake от кнопок, переключение между 9 экранами |

**Проводка кнопок:** один контакт каждой кнопки на GND, второй на
GPIO 4 (кнопка «показатель») и GPIO 5 (кнопка «период»). Внешние
резисторы не нужны.

**Команды:**
```bash
git checkout 7c11374
pio run -e esp32-s3-supermini -t erase     # сбросить RTC, иначе current_screen
                                            # от предыдущей версии может быть мусором
pio run -e esp32-s3-supermini -t upload -t monitor
```

**Ожидаемое поведение:**
1. После прошивки — обычный цикл измерений.
2. Нажатие кнопки «показатель» (GPIO 4) → wake → лог
   `PARAM button: screen 0 → 3` → экран обновляется с новым заголовком.
3. Нажатие кнопки «период» (GPIO 5) → `PERIOD button: screen 0 → 1`.
4. Удержание кнопки 2 сек → wake, переключение, и `wait_for_button_release`
   ждёт отпускания (виден лог «timeout» если держать > 3 сек).

**Диагностика:**
- ❌ **Кнопки ничего не делают.**
  - Прозвонить: при нажатой кнопке между GND и GPIO 4/5 должна быть
    проводимость.
  - Если контакт есть, но wake не происходит — проблема с pull-up.
    Проверить лог: при нажатии в Serial должно быть «cause: 6 (BUTTON)».
- ❌ **ESP пробуждается сам по себе (без нажатия).**
  - Электрические наводки на GPIO 4/5. Укоротить провода, перепаять
    контакты. В крайнем случае — добавить внешние pull-up 10 кΩ.
- ❌ **После одного нажатия ESP застревает (постоянно «BUTTON wake»).**
  - Кнопка залипла или плохой контакт даёт постоянный LOW. Прозвонить.

| | |
|---|---|
| Commit | `2467e26` |
| Подключения | те же |
| Цель | Каждое измерение пишется в `/data/measurements_001.bin` |

**Команды:**
```bash
git checkout 2467e26
pio run -e esp32-s3-supermini -t erase     # очистить LittleFS
pio run -e esp32-s3-supermini -t upload -t monitor
```

**Ожидаемый Serial:**
```
First boot — RTC initialized
LittleFS mount failed, formatting...
LittleFS formatted and mounted
Created /data directory
LittleFS: 0 / 1441792 bytes used
SCD41 OK. SN: 0x...
CO2: 645 ppm, T: 23.4 C, H: 45 %
Saved to /data/measurements_001.bin: +10 B, total 10 B (1 records)
Sleeping for 300 sec.
```

После каждого пробуждения должно быть `total NN B (N records)` с
растущим количеством записей.

**Диагностика:**
- ❌ **«LittleFS format failed too».**
  - Раздел повреждён. Запустить ещё раз `pio run -t erase`.
- ❌ **«save_measurement: invalid».**
  - Датчик вернул значения вне диапазона. Норма для первых пары циклов,
    проблема если повторяется.
- ❌ **Записи добавляются по 12 байт, а не 10.**
  - `static_assert(sizeof(Measurement) == 10)` должен был это поймать
    на сборке. Если каким-то образом сборка прошла — пересобрать
    с `pio run -t clean`.

### Этап 8 — Ротация файлов

| | |
|---|---|
| Commit | `fd661d5` |
| Подключения | те же |
| Цель | При 90 КБ → новый файл, при >13 файлов → удаление старого |

**Проблема проверки:** реально получить 9000+ измерений = 31 день.
Для быстрой проверки можно временно уменьшить `MAX_FILE_SIZE` в
`src/main.cpp` (например, до `512` байт = ~50 измерений = ~4 часа
работы или ~5 минут при ускорении).

**Альтернатива — ускоренный тест:**

1. В `src/main.cpp` временно изменить:
   ```cpp
   #define MAX_FILE_SIZE  (200)           // ≈ 20 записей
   #define MEASUREMENT_INTERVAL  10       // вместо 300 — пробуждаться каждые 10 сек
   ```
2. Перепрошить, посмотреть как через минуту-две в `/data/` появляются
   `_002.bin`, `_003.bin`...
3. После 13 файлов — должен исчезнуть `_001.bin`.
4. **ВЕРНУТЬ значения обратно** и перепрошить.

**Ожидаемый Serial при ротации:**
```
Saved to /data/measurements_001.bin: +10 B, total 90112 B (9011 records)
File reached 90112 bytes (limit 92160), rotating...
Rotated to /data/measurements_002.bin
```

При удалении старого:
```
Deleted oldest: /data/measurements_001.bin
```

### Этапы 9–10 — Графики

| | |
|---|---|
| Commits | `ec85b31` (Этап 9), `f96816b` (Этап 10) |
| Подключения | те же |

**Этап 9:** на экране 0 (CO2 1h) видны столбики. На остальных — заглушка.

**Этап 10:** на всех 9 экранах — реальный график. Нажатие кнопки
«показатель» → CO2 → T → H. Кнопка «период» → 1h → 24h → 7d.

**Сколько данных нужно чтобы график выглядел осмысленно:**
- 1h: 12 измерений = 60 минут работы.
- 24h: 288 измерений = 24 часа.
- 7d: 2016 измерений = 7 дней.

В первые часы графики 24h и 7d будут пустыми (заполняются справа налево
по мере накопления).

**Диагностика:**
- ❌ **График пустой даже после часа работы.**
  - LittleFS пуст. Проверить что Этап 7 работал: `pio device monitor`
    должен показывать «Saved to ... N records».
- ❌ **Столбики кажутся слишком высокими/низкими.**
  - Шкалы `CO2_SCALE_MIN/MAX`, `TEMP_SCALE_MIN/MAX`, `HUMIDITY_SCALE_MIN/MAX`
    в `main.cpp` можно скорректировать.

1. Прошить финальный код (`git checkout main`).
2. Проверить что работает от USB как ожидается.
3. Прислать пользователя ВЫНУТЬ USB.
4. ВСТАВИТЬ батарейки в бокс.
5. Проверить мультиметром на разъёме бокса: красный +, чёрный −,
   `+4.5 В ± 0.2 В` на свежих батарейках.
6. Если полярность правильная — подключить **красный к пину 5V**,
   чёрный к GND.
7. Если на экране сохранилась картинка с предыдущего цикла — отлично.
   В течение 5 минут должно произойти первое пробуждение от батарей.

**Если ничего не происходит после 6 минут:**
- Замерить мультиметром напряжение между 5V пином и GND ESP — должно
  быть `~4.5 В`. Если `0 В` — нет контакта в боксе или плохая пайка.
- Замерить между 3V3 и GND ESP — должно быть `~3.3 В`. Если `0` —
  LDO ESP не работает, возможно мало напряжения на входе.

**Энергопотребление (требует USB-амперметра или setup попроще):**
- Sleep: < 100 мкА (в идеале ~30 мкА).
- Wake + измерение: ~50 мА в течение 6 сек.
- Refresh экрана: ~30 мА в течение 0.5–2 сек.

## Параметры для подкрутки

Все в `src/main.cpp`, ищи `#define`:

| Параметр | Когда менять |
|---|---|
| `EPD_DRIVER` | Экран ничего не показывает — перебрать B73 → B72 → BN → DEPG0213BN |
| `LED_PIN` | LED на другом пине или его нет (для Этапа 1) |
| `LED_LEVEL` | LED слишком яркий/тусклый (0–255) |
| `MEASUREMENT_INTERVAL` | Чаще/реже замеры (по умолчанию 300 = 5 мин). Удвоение → +2× к автономности |
| `FULL_REFRESH_INTERVAL` | Экран показывает призраков → уменьшить (например 1800) |
| `TEMPERATURE_OFFSET` | Не реализован в коде; добавить в `take_measurement` если калибровать |
| `CO2/TEMP/HUMIDITY_SCALE_MIN/MAX` | Подкрутка шкал графиков |
| `CO2_THRESHOLD_HI`, `ALERT_CO2_ON/OFF` | Если 1500/1300 не подходят |
| `IDEAL_CO2/TEMP/HUMIDITY` | Положение «идеальной» линии на графике |
| `SHOW_IDEAL_LINE`/`SHOW_AVERAGE_LINE`/`SHOW_THRESHOLD_BAD` | Скрыть лишние линии |
| `VERBOSE_LOGGING` | 0 на батарее — меньше шума в Serial (на потребление не влияет) |
| `MAX_FILE_SIZE`, `MAX_FILES` | Только для ускоренной проверки ротации (Этап 8) |
| `AVERAGE_RECALC_INTERVAL` | Только для ускоренной проверки средних (Этап 13) |

После любых изменений: `pio run -t upload`.

## База типичных проблем (быстрый поиск)

**E-Paper полностью белый / мусор.**
→ Сменить `EPD_DRIVER` (см. Этап 3).

**SCD41 «not responding».**
→ Провода, адрес 0x62 (`pio device monitor` после прошивки I2C-сканера —
если нужно, написать отдельный sketch).

**В sleep ESP потребляет много (заметно по аккумулятору).**
→ Проверить что `scd4x.powerDown()` выполнился перед sleep (в Serial
«Sleeping»). Внешние pull-up на I2C могут жрать ток — обычно ОК на 3.3 В
с резистором 10 кΩ это 0.33 мА, многовато для бюджета. Если есть pull-up
1 кΩ — это 3.3 мА, очень плохо.

**Кнопка вызывает ESP несколько раз подряд.**
→ Дребезг. `wait_for_button_release` после wake должен это поглощать.
Если нет — увеличить `delay(50)` в конце функции до `delay(150)`.

**LittleFS повредился после внезапного отключения питания.**
→ Запустить `pio run -t erase`, измерения с этого момента — заново.

**После замены батарей всё забыто.**
→ Норма. `RTC_DATA_ATTR` не переживает power-off, только sleep.
`uptime` обнуляется. Сохранённые в LittleFS данные сохраняются.

**Экран показывает призраков (тени старого).**
→ Уменьшить `FULL_REFRESH_INTERVAL` или сделать раз в N циклов full refresh
вместо partial. Прокомментировать `display.hibernate()` если хочется
протестировать без него.

**Текст налезает на светофоры / друг на друга.**
→ Подбор пикселей в `draw_header`, `draw_y_labels`, `draw_x_labels`,
`draw_alert_if_needed`. Сборка → прошивка → визуальная проверка.

## Что говорить пользователю если этапы не нужно проходить по очереди

Если пользователь уже знаком с прошивкой и говорит «у меня всё подключено,
запускай финал»:

1. `git checkout main`
2. `pio run -e esp32-s3-supermini -t erase`
3. `pio run -e esp32-s3-supermini -t upload -t monitor`
4. Смотрим в Serial. Если что-то не так — диагностика по типичным
   проблемам выше.

Но **всё равно рекомендовать** хотя бы Этапы 1, 2, 3 пройти отдельно —
изоляция проблем в случае чего сильно быстрее.
